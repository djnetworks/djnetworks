1. The User

An established textile-trade owner or operator. Expert in the trade; cautious with software. The product does not need to make them technology-first — it must become trade-first.

Observed audiencePhase 1 operating context

The emotional contract

Ekum is always one confusing moment away from losing the user to WhatsApp. Resistance is rarely “I do not understand textiles.” It is “I do not understand what this screen wants from me.” The interface must remove the second feeling without ever insulting the first.

The hard floor

Design for a person standing on a busy market floor, phone in one hand, someone talking in their ear, using an older Android over 3G. This is the primary device-and-context test, not an edge case.

5. Navigation & Wayfinding

A tab is a destination a user returns to daily. An action is a button. Anything used occasionally is one level down. The core job should never sit more than one level below a daily destination.

Decision required
Product brief / vision

Option A — Three shared tabs

Home, Discover and Orders remain constant for buyer, supplier and trader. Content adapts by role; chat opens inside a supplier relationship rather than taking a permanent tab.

HomeDiscoverOrders

Benefit: the same account never has to relearn the footer. Risk: “Discover” needs a role-specific meaning for suppliers and may compete with their own collection work.

Brand Kit / contextual intent

Option B — Role-appropriate destinations

All roles keep the same interaction grammar, but destinations match the job: a supplier sees Home, Collections, Orders and Chats; a raised action starts upload; a buyer’s discovery remains distinct.

HomeCollections＋ChatsMore

Benefit: each job is named honestly. Risk: role switching changes navigation and adds a learning burden unless the role context is very clear.

Recommendation

Hold the confirmed 3-tab information architecture for Phase 1, but make each destination role-adaptive — not merely relabelled.

The Product Vision and Phase 1 Brief explicitly lock Home / Discover / Orders across roles, while the Brand Kit illustrates a five-item navigation component. Treat this as a source conflict, not a styling detail. For the first shipped build, preserve the locked 3-tab model to avoid re-opening a confirmed product decision; define each role’s “Discover” content as its collection world. Before visual implementation begins, product owners must formally reconcile this with the Brand Kit’s five-item example.

6. Information Hierarchy & Density

On a market floor, the user does not read a screen. They recognise it. A usable surface answers what this is, whether it needs attention and what to do next within a glance.

The three-second content order

Lead with the thing the user came for — almost always an image, name or action. Numbers serve as proof or context, not as the focal point. Keep secondary information one tap deeper.

1
Identify the object or personPhoto, business name, collection name, order identifier.
2
Show only one important changeNew photos, an order to confirm, a rate to decide, a request to approve.
3
Make one next action obviousOpen, confirm, add photos, request access, publish.

Density limits

Lists outperform KPI tiles for daily work because they explain both what changed and what to do. Use metrics only as secondary evidence once a task surface is already understood.

A
One highlight per screenFollow the Brand Kit’s restrained Tangerine rule. A second “look here” signal weakens the first.
B
One status signal per rowDo not stack badge, dot, warning text and a CTA onto the same list item.
C
Image first, text secondIn catalogue contexts, photography carries recognition. Metadata stays brief and subordinate.

In this market, trust is a product behaviour. Privacy, access and commitment clarity cannot be hidden behind settings because they are the reason a supplier leaves an unstructured WhatsApp flow.

8. Language & Localisation Behaviour

This part explains how language affects layout and interaction. For exact wording, button labels and message tone, defer to the Messaging & Copywriting Guide.

English only in Phase 1

Icons need labels

An unlabelled icon asks the user to guess. Pair navigation and action icons with plain words, particularly on mobile. The Brand Kit provides the icon system; this rule defines its behavioural use.

Numbers are familiar; software words are not

Prices, sets, pieces, rates and dispatch are native trade language. Lead with them where relevant. Avoid product vocabulary that requires interpretation; apply the Messaging Guide’s Ring Road test before ship.

Reading comfort varies; image recognition does not

Keep text short and support recognition through photos, names, numbers and repeated placement. The goal is not to reduce trade complexity; it is to reduce software decoding.

Resolved Phase 1 constraint

The current Product Vision locks Phase 1 to English, with Hindi and Gujarati planned for Phase 2. Design labels must still survive future expansion: avoid fixed-width text containers, preserve icon-plus-label patterns and do not use English text as decoration.
